# Herdr Autoname 视觉系统

状态：本地设计与实现说明，2026-10-01。项目名称中的 Emoji 是命名内容，保持现有生成逻辑；视觉系统只整理排版、状态颜色和辅助标识。

## 1. 要解决的问题

侧栏同时承载「有没有事需要处理」「这是什么任务」「在哪个项目、由哪个 Agent 处理」。旧格式把彩色状态点、Emoji、方括号和标题挤在同一行，窄侧栏里标题很快被截断。用户需要先认出工作空间，再看 Agent 当前任务。

新的阅读顺序：**项目目录 → 树枝 + 原有 Emoji + 短标题**。`├` / `└` 表示 Workspace 隶属上方的项目目录；运行状态在下方 Agents 列表显示。Emoji 是项目名称的一部分，继续帮助定位任务。

## 2. 侧栏结构

```text
Spaces
Local                            ← Herdr 的机器分组
   pika_work · main ✱1          ← 项目目录／Git 信息，作为任务父层
    ├ 🔍 FlashVAE更新分析        ← 同项目还有后续 Workspace
    └ 💬 Slack频道人物志          ← 同项目最后一个 Workspace

   food-officer                  ← 另一个项目目录
    └ 🍱 Food Officer             ← 单个 Workspace 也用 └

Agents
● 🔍 FlashVAE更新分析          ← 第一行：状态、与 Spaces 相同的 Workspace 名称
     排查 FlashVAE 结果       ← 第二行：Agent 图标、当前任务文字
```

| 元素 | 用途 | 谁控制 |
| --- | --- | --- |
| `├` / `└` | 项目目录下的 Workspace 树形关系；同一项目最后一项用 `└` | Autoname 的显示元数据 |
| Agents 左侧状态点 | 工作中、等待、空闲、错误等运行状态 | Herdr 的 `state_icon` 与主题 |
| 名称中的 Emoji | 快速辨别任务类别；Workspace、Tab、Pane 沿用同一 Emoji | Autoname 原有命名逻辑 |
| 第一行文字 | Spaces 与 Agents 显示同一个 Workspace 稳定主题 | Autoname 命名与显示元数据 |
| 项目父行／Agent 第二行 | 项目、Git 状态、Agent 图标及 Pane 当前任务文字 | Autoname 元数据和 Herdr 侧栏布局 |
| 缩进、截断、选中底色 | 窄侧栏布局与当前选中项 | Herdr |

本次排版调整去掉标题外侧的 `[` `]`，把项目目录移到任务列表上方，并使同一目录下的树枝对齐。Herdr 会把带项目标题的首条任务自动缩进两格；插件给后续任务补同宽的显示缩进。Spaces 列表专注展示目录关系，运行状态点留在 Agents 列表。Agents 第一行与 Spaces 的 Workspace 标题保持一致，第二行只展示 Agent 图标和 Pane 当前任务文字，省去重复的 Agent 名称与 Emoji。树枝只存在侧栏，不写入 Workspace、Tab、Pane 名称。空白 Pane 在没有任务证据时显示 `💤 等待任务`。

### 截图中的例子

```text
旧：○ [🔍 FlashVAE更新分析]
新： pika_work · main ✱1
      ├ 🔍 FlashVAE更新分析

旧：○ [🍱 Food Officer]
新： food-officer
      └ 🍱 Food Officer

旧：● [🏷️ Herdr自动命名]
新： projects
      ├ 🏷️ Herdr自动命名
```

Agents 示例中的 `●` / `○` 只是位置示意；真实颜色和形状取决于 Herdr 状态及当前主题。

## 3. 颜色

当前 Herdr 配置使用 `catppuccin-latte`、`status_indicators = "dots"`，且关闭自动明暗切换。状态点和选中底色由 Herdr 控制；插件按 Herdr 的 Agent 状态给 Agents 两行文字上色，并在状态事件到来时立即切换显示字段。配色取自当前浅色主题，切换主题时需要重新检查对比度。

| Agent 状态 | 标题与任务文字 | 用途 |
| --- | --- | --- |
| `working` | 暖黄 `#df8e1d` | 正在处理 |
| `blocked` | 红 `#d20f39` | 需要人处理 |
| `done` | 绿 `#40a02b` | 已完成 |
| `idle` | 灰 `#6c6f85` | 暂无活动 |
| `unknown` | 浅灰 `#9ca0b0` | 状态未确认 |

任务类别继续由名称中的 Emoji 辅助识别；颜色只代表运行状态，不代表项目类别。

插件设置弹窗是 curses TUI，使用终端调色板而非固定十六进制色：

| 弹窗元素 | 当前处理 |
| --- | --- |
| 标题、分区标题 | 青色、加粗 |
| 当前选中项 | 黑字青底、加粗 |
| 可执行操作 | 黄色、加粗 |
| 成功反馈 | 绿色、加粗 |
| 普通与说明文字 | 终端默认前景色 |
| 无彩色终端 | 加粗和反显，保留可读性 |

颜色只加强层级；不用颜色单独传递一个必须知道的操作或状态。

## 4. 图标语言

**名称中的 Emoji 保持原样。** 模型仍按原有规则，为 Workspace、Tab、Pane 生成同一 Emoji 加各自的主题或动作。插件不把 `🔍`、`🍱`、`🏷️` 等 Emoji 转成 Nerd Font，也不替没有 Emoji 的项目名称添加图标。`├` / `└` 是项目父行下面的侧栏树枝，不属于名称。排版通过项目父行、树枝、去掉方括号和控制文字长度来改善。

Nerd Font 只用于名称之外的辅助身份标识：项目父行显示 ``，Agent 第二行使用 ``（Codex）、``（Claude）、``（OpenCode 或 Shell）。私有字形依赖 Nerd Font 或终端字体回退；当前终端实测可见。Agent 来源由图标表示，任务文字保持可读。

## 5. TUI 状态标识

CLI 与设置弹窗预览没有直接复用 Herdr 的彩色 `state_icon`，使用独立的纯字符状态表。它们属于**状态标识**，不会成为名称的一部分：

| 状态 | TUI 字符 | 含义 |
| --- | --- | --- |
| `working` | `▶` | 正在工作 |
| `idle` | `○` | 空闲 |
| `waiting` | `◌` | 等待输入或外部结果 |
| `error` | `✕` | 出错 |
| `completed` / `done` | `✓` | 完成 |
| `unknown` | `·` | 状态未知 |

设置弹窗继续以 Provider、Model、自动改名、频率、预览、立即改名、保存为主路径。预览在标题行展示 Workspace 与状态；第二行展示 Agent 图标和当前任务文字。用户无需记住图标含义才能操作，图标只提高扫视速度。

## 6. 文案和布局约束

- Workspace 写稳定的工作主题；Tab 写更短的分类；Pane 写当前动词与对象。
- 不显示包裹标题的方括号；保留命名模型生成的项目 Emoji，不把运行状态点写进名称。
- Pane 名称沿用现有最大显示宽度 28 列；超长内容优先缩短文字，保留任务对象。
- 项目／Git 信息只在同组首项上方展示一次，作为这一组 Workspace 的父行。
- 新 Workspace 尚未得到任务名、且名称仍等于项目目录时，侧栏暂显示「新会话」；纯 Shell 显示「终端」。实际 Workspace 名称不会因此改动，自动命名后显示任务名。
- 对于还没有会话 ID 或对话记录的 Pane，优先使用可见终端标题；没有可用任务线索时用 `💤 等待任务`。
- 图标由字符和字体渲染，不能把 SVG 文件直接嵌进终端字符流。自定义品牌图标需要字体提供相应码位。

## 7. 验收范围

这份规范描述目标排版。检查时应分别确认：插件产出的 Emoji 名称没有被替换、Herdr 保存的元数据、实际侧栏渲染、设置弹窗预览。至少覆盖正在工作、等待、空闲、无会话 ID 的 Pane，以及窄侧栏截断。若 Agent 品牌字形在其他终端缺失，优先选可用的 Nerd Font 字形或保留文字标签。
